# Урок 12 — Персонализация ассистента

Отдельное FastAPI + Streamlit-приложение: профиль пользователя, предпочтения и
автоматическое обогащение профиля из диалога. Профиль подключается к system prompt
каждого запроса.

## Что реализовано

1. **Профиль пользователя** — имя, роль, город, язык, часовой пояс.
2. **Предпочтения** — стиль общения (формальный/неформальный), формат ответа, примеры кода (с/без), emoji (с/без), ограничения.
3. **Профиль в каждом запросе** — профиль и предпочтения всегда добавляются в
   system prompt; в контексте явно видно, какие поля заполнены, а какие нет.
4. **Автообогащение из диалога** — из реплик извлекаются устойчивые факты:
   - «Меня зовут …» → имя;
   - «Я работаю …» → роль;
   - «Я живу в …» / «Мой город …» → город;
   - «на ты» / «на вы» / «формально» → стиль;
   - «кратко» / «подробно» / «списком» / «таблицей» → формат;
   - «с примерами кода» / «без примеров кода» → примеры кода;
   - «с emoji» / «без emoji» → emoji;
   - «без воды» / «не используй …» → ограничения.

Каждое изменение фиксируется в `history` с источником `пользователь` или `диалог`.

## API

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/health` | состояние урока и список полей |
| `GET` | `/api/profiles` | список профилей для переключения |
| `GET` | `/api/profile?owner_id=demo` | профиль, предпочтения, история |
| `POST` | `/api/profile` | сохранить профиль вручную |
| `DELETE` | `/api/profile?owner_id=...` | удалить профиль, предпочтения и историю |
| `POST` | `/api/preferences` | сохранить стиль / формат / ограничение |
| `DELETE` | `/api/preferences/{key}` | удалить предпочтение |
| `GET` | `/api/context` | system prompt с профилем и историей |
| `POST` | `/api/chat` | автообогащение профиля и ответ модели |
| `POST` | `/api/chat/reset` | очистить только историю диалога |
| `POST` | `/api/profile-check/question` | новый некешируемый вопрос проверки |
| `POST` | `/api/profile-check/all` | один вопрос всем профилям |
| `POST` | `/api/profile-check/batch` | 10 случайных вопросов разным профилям |
| `POST` | `/api/profile-check/analyze` | анализ результатов моделью `deepseek-v4-pro` |

`POST /api/chat` сначала извлекает факты из сообщения, сохраняет их, затем собирает
system prompt с уже обновлённым профилем. В ответе есть `updates`, `profile`,
`context`, `request_tokens` и `response_tokens`.

API отдаёт `Cache-Control: no-store`; база — SQLite `/srv/data/profile.db`.

## UI

Общий интерфейс: раздел **«Персонализация ассистента (урок 12)»**.

В сайдбаре — переключатель текущего профиля, счётчик профилей и удаление текущего
профиля с подтверждением. Для теста предзаполнены пять профилей: `demo`, `test-alice`
(Анна: формально, без кода, без emoji), `test-elena` (Елена: формально, без кода,
с emoji), `test-ivan` (Иван: неформально, с кодом, с emoji), `test-olga`
(Ольга: неформально, с кодом, без emoji).

Вкладки (первая — чат):

- **Чат с профилем** — диалог, автообновления из реплик и просмотр профиля,
  который ушёл в последний запрос;
- **Профиль** — ручное заполнение имени, роли, города, языка и часового пояса;
- **Предпочтения** — стиль, формат, примеры кода, emoji и ограничения, источник и уверенность;
- **Контекст** — фактический system prompt с профилем и историей;
- **Проверка профилей** — уникальный вопрос для всех профилей, серия из 10 случайных
  вопросов разным профилям и анализ результатов моделью `deepseek-v4-pro` из OpenCode Go.
  Вопросы генерируются на сервере, не кешируются и имеют уникальный `question_id`.
  В серии вопросы подбираются под специализацию профиля; при общем вопросе профиль
  обязан обозначить границу роли и не отвечать как универсальный эксперт.
  Ответы при обрыве автоматически дописываются; для профиля с «с примерами кода»
  ответ проверяется на наличие блока кода. Лимит ответа — 1600 токенов, ответы
  запрашиваются компактными. Вкладка считает соблюдение предпочтений по ответам,
  показывает первый ответ с нарушением и проверяет устойчивость профилей после
  серии из 10 вопросов.

## Запуск

В общем стеке:

```bash
docker compose up -d --build
open http://localhost:8500
```

API через шлюз: `http://localhost:8000/lesson-12/api/health`.

Изолированно:

```bash
cd "Lesson 12/app"
docker compose up -d --build
open http://localhost:8512
curl http://localhost:8012/api/health
```

Порты: UI `8512`, API `8012`.

## Тесты

```bash
docker compose -f "Lesson 12/app/docker-compose.yml" run --rm api python -m pytest -q
```
