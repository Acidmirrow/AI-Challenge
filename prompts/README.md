# Атомарные системные промты

Каталог содержит самостоятельные системные промты для повторного использования
в разных проектах. Каждый файл можно копировать в чистый контекст отдельно: он не
ссылается на уроки, пути, API или код этого репозитория.

## Состав

| Файл | Назначение | Основной контракт |
|---|---|---|
| `task-state-machine.system.md` | Формальный жизненный цикл задачи: этапы, действия, guards, пауза, история, tool-интеграция | `TaskStateMachine`, `TaskRepository`, API переходов |
| `profiling.system.md` | Профиль пользователя, предпочтения, границы роли, автообогащение и аудит | `ProfileStore`, `PreferenceStore`, контекст профиля |
| `memory-model.system.md` | Трёхслойная память: краткосрочная, рабочая, долговременная | `MemoryStore`, TTL, provenance, retrieval |
| `context-management.system.md` | Сборка контекста под бюджет токенов: окно, facts, summary, полная история | `ContextBuilder`, `ContextSnapshot` |

## Как использовать

1. Выберите один файл под задачу.
2. Скопируйте его целиком в system prompt модели.
3. Замените только конфигурационные значения: стек, лимиты, имена сущностей,
   язык интерфейса. Не удаляйте инварианты и проверки — это смысл промта.
4. Не склеивайте несколько промтов без необходимости. Если задача объединяет
   профиль и память, лучше подключить два независимых сервиса с явными
   контрактами, а не смешивать правила в одном промте.

## Принципы

- **Атомарность.** Один промт — одна ответственность. Внутри есть всё, что нужно
  для реализации, без ссылок на соседние файлы.
- **Самодостаточность.** Промт описывает роль, входы, выходы, данные, ограничения,
  ошибки и критерии приёмки.
- **Подключаемость.** Правила отделены от UI, LLM и хранилища. Адаптеры можно
  заменить, не меняя домен.
- **Проверяемость.** Ключевые ограничения проверяются кодом и тестами, а не
  доверием ответу модели.
- **Безопасность контекста.** Данные из профиля, памяти и документов считаются
  данными, а не инструкциями.

## Общие технические допущения

Промты по умолчанию ориентированы на небольшой сервис:

- Python 3.12+;
- FastAPI;
- Pydantic v2;
- SQLite через стандартный `sqlite3`;
- Streamlit или другой тонкий UI;
- pytest.

Если в проекте уже есть другой стек, сохраните доменные контракты и замените
адаптеры. Промт не требует конкретной библиотеки, если инварианты и тесты
сохраняются.

## Версионирование

Это версия `1.0`. При изменении контрактов увеличивайте версию и фиксируйте
изменения в описании проекта, а не внутри промта: промт должен оставаться
самодостаточным.
