# Урок 14 — Инварианты и ограничения состояния

Отдельное FastAPI + Streamlit-приложение, в котором ассистент обязан
соблюдать инварианты проекта. Инварианты хранятся отдельно от диалога, а их
нарушение проверяется кодом до вызова модели и после получения ответа.

## Инварианты

| ID | Категория | Ограничение |
|---|---|---|
| `INV-001` | Архитектура | Сервисы общаются только через HTTP REST или асинхронные события; прямые синхронные вызовы и общая память запрещены. |
| `INV-002` | Стек | Python 3.12, FastAPI, Streamlit, SQLite; нельзя добавлять PostgreSQL, MySQL, MongoDB, Redis, Kafka, RabbitMQ и другие фреймворки без отдельного решения. |
| `INV-003` | Хранение | Данные хранятся в локальной SQLite; S3 и внешние файловые хранилища не используются. |
| `INV-004` | Безопасность | Ключи и пароли не хранятся в коде, git или чате; только gitignored secrets.properties, `.env` или keychain. |
| `INV-005` | Бизнес | Нельзя обещать или добавлять функции вне текущего MVP без явного решения об изменении объёма. |

Инварианты лежат в SQLite (`invariant`), а не в истории сообщений. История
изменений — `invariant_change`: кто, когда, старое и новое значение. Те же
инварианты зафиксированы в общих правилах (`docs/RULES.md`, R-016) и в
переиспользуемом системном промте `prompts/invariants.system.md`.

## Проверка кодом

Порядок обработки запроса:

1. **Pre-check** — `check_text()` проверяет сообщение пользователя по
   регулярным правилам, привязанным к ID инварианта. При совпадении модель
   не вызывается; возвращается детерминированный отказ с причиной.
2. **Модель** — получает системный промпт с активными инвариантами и должна
   вернуть JSON с `decision`, `invariants_considered`, `reasoning`, `answer`.
3. **Post-check** — ответ модели повторно проверяется тем же кодом. Если
   модель всё же предложила запрещённое решение, ответ заменяется отказом.

Отрицательные упоминания («не используйте PostgreSQL») не считаются
нарушением: проверка учитывает контекст отрицания.

## Изменение инварианта

Только явная команда в отдельной панели, не обычное сообщение чата:

```text
!invariant INV-002 => новый текст инварианта
```

API: `POST /api/invariants/change` с полями `command`, `reason`, `changed_by`.
История доступна через `GET /api/invariants/history`. Сообщение с
`!invariant` в обычном чате не меняет инвариант — API возвращает отказ.

## Попытки обхода

`POST /api/bypass-test` прогоняет 9 формулировок: 8 базовых векторов
(исключение, «просто для примера», «забудь ограничения», ролевая подмена,
прямой вызов без HTTP, hardcode секрета, функция вне MVP, Kafka) и отдельный
найденный обход через управляемую облачную БД. Каждая попытка фиксируется в
таблице `attempt`; результат содержит `total`, `blocked`, `escaped`.

Найденный обход **намеренно не исправлен**: 9-я попытка проходит
(`escaped = 1`), остальные 8 блокируются. Это отдельный пункт для ручной
демонстрации ограничения текущего код-чекера.

## API

Все запросы к чату и попыткам используют заголовок `X-Session-Id`.

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/health` | состояние сервиса |
| `GET` | `/api/invariants` | список инвариантов |
| `POST` | `/api/invariants/change` | явное изменение по команде |
| `GET` | `/api/invariants/history` | история изменений |
| `POST` | `/api/chat` | запрос с pre-check, моделью и post-check |
| `GET` | `/api/chat/history` | история чата |
| `POST` | `/api/bypass-test` | 9 попыток обхода |
| `GET` | `/api/attempts` | попытки и статистика |
| `POST` | `/api/clear` | очистить чат и попытки с подтверждением |

Ответ `/api/chat` содержит `decision` (`allow`, `refuse`, `error`),
`answer`, `violations`, `invariants_considered`, `source` и статистику
`attempts`.

## UI

Отдельная страница: `http://localhost:8514`.
В общем интерфейсе — раздел **«Инварианты и ограничения состояния (урок 14)»**.

Вкладки:

- **Проверка ассистента** — инварианты, чат, быстрые конфликтующие запросы;
  у ответа видны решение, источник проверки, учтённые инварианты и нарушения;
- **Обход инвариантов** — кнопка запуска 9 попыток, таблица результатов,
  метрики «всего / заблокировано / прошло», найденный обход и история попыток;
- **Управление инвариантами** — выбор инварианта, новый текст, явная команда
  `!invariant <ID> => ...`, причина и история изменений.

В сайдбаре — счётчик активных инвариантов и очистка истории чата/попыток.
