# AI Challenge — уроки 01–10

Учебный проект: каждый урок — отдельное приложение (FastAPI + Streamlit), но весь
курс открывается **с одного хоста и одного порта**.

> Вся документация собрана в `docs/`. Пути к коду в тексте указаны от корня
> репозитория.

Краткая карта всех уроков (обновляется по мере завершения) — [`LESSONS_SUMMARY.md`](LESSONS_SUMMARY.md).

```
UI:   http://localhost:8500     # общий интерфейс, разделы всех уроков
API:  http://localhost:8000     # шлюз: /lesson-01/api/..., … /lesson-10/api/...
```

Уроки 01–10 реализованы; урок 10 сравнивает стратегии управления контекстом.

## Как это устроено

```
docker-compose.yml        # единственный стек: 10 API + шлюз + один фронт
gateway/                  # прокси: разводит /lesson-0X/api/* по сервисам
Lesson 01/app/            # код урока 01: api/ (FastAPI) + front/ (страницы) + config/
Lesson 02/app/            # код урока 02 — отдельно, ничего общего с уроком 01
Lesson 03/app/
Lesson 04/app/
Lesson 05/app/
Lesson 06/app/            # здесь же общий фронт уроков 01–09
Lesson 07/app/            # сохранение контекста: API + SQLite + отдельный фронт
Lesson 08/app/            # работа с токенами: API + отдельный фронт
Lesson 09/app/            # управление контекстом: API + отдельный фронт
Lesson 10/app/            # сравнение стратегий: API + отдельный фронт
```

Логика каждого урока живёт **в своей папке**: у него собственные `app/api/app/*`,
`app/config/*`, тесты и `docker-compose.yml` для изолированной работы. Общий стек
ничего не смешивает — он только собирает эти приложения и публикует их за одним
адресом.

Шлюз (`gateway/`) отдаёт:

| Путь | Назначение |
|---|---|
| `GET /health` | `{"status": "ok", "lessons": [...]}` |
| `GET /api/lessons` | список уроков и их префиксов |
| `/{lesson}/api/*` | проксирование в API урока, включая SSE-стриминг |

Неизвестный урок → `404`, недоступный апстрим → `502` с понятным текстом.

## Быстрый старт

```bash
docker compose up -d --build

```

Порты можно переопределить: `API_PORT=8080 FRONT_PORT=8600 docker compose up -d`.

## Модели и провайдеры

- Основной провайдер — DeepSeek (`provider = deepseek` в `config/app.properties`),
  модели `deepseek-flash` и `deepseek-v4-pro`.
- Бесплатные провайдеры — OpenRouter и Nous Portal: включаются по ключу,
  список моделей читается из их `/models` при старте (до трёх подходящих на
  провайдера, у Nous Portal — до четырёх),
  `POST /api/models/refresh` перечитывает без перезапуска. Gemini остаётся
  в API, но во фронте скрыт.
- Nous Portal (`https://inference-api.nousresearch.com/v1`, ключ `nous.api.key`)
  отдаёт бесплатные модели с суффиксом `:free`: `stepfun/step-3.7-flash`,
  `upstage/solar-mini4`, `meituan/longcat-2.5`, `reflection/beam-1.0-501b-a23b`.
- Без статического ключа Portal можно ходить через локальный broker-прокси Hermes:
  `hermes proxy start --provider nous --host 127.0.0.1 --port 8645`, а в gitignored
  `Lesson 0X/app/config/secrets.properties` указать
  `nous.base.url = http://host.docker.internal:8645/v1`,
  `nous.api.key = local-proxy` и `nous.host.header = 127.0.0.1:8645` (прокси
  принимает только loopback-Host, поэтому контейнер подставляет его явно).
- Если `/models` недоступен (сеть, гео-блок, `403`), в каталоге остаются запасные
  списки: OpenRouter — `nemotron`/`gemma`, Nous Portal — те же четыре `:free`-модели.
  Живой список всегда важнее запасного.
- Выбор модели во всех разделах — один и тот же поповер `⚙ <модель> ▾` с
  группировкой по провайдерам.
- Урок 05 сравнивает модели трёх размеров: каждая модель помечена `small` /
  `medium` / `large` (у известных — в каталоге, у бесплатных — по числу параметров
  в имени), поэтому в сравнении три слота: маленькая, побольше, большая.
- Индикаторы в сайдбаре показывают доступность: `🟢` отвечает, `🟠` ключ есть но
  провайдер не отвечает, `⚪` ключа нет.

## Стоимость прогона (урок 05)

`POST /api/compare` считает стоимость по прайсу из
`Lesson 05/app/config/pricing.properties` — доллары за 1 млн токенов, отдельно
вход и выход. Бесплатные провайдеры — `0` с пометкой «бесплатный провайдер»,
неизвестная модель — `0` с пометкой «цена не задана». Файл лежит в git и
читается при старте API.

## Ключи и конфигурация

У каждого урока свой `Lesson 0X/app/config/`:

- `app.properties` — в git, без секретов (провайдер, base_url, лимиты);
- `pricing.properties` — в git, только цены моделей (есть у уроков 05–06);
- `secrets.properties` — gitignored, монтируется в контейнер при деплое
  (`deepseek.api.key`, `gemini.api.key`, `openrouter.api.key`, `nous.api.key`).

Пример лежит рядом: `secrets.properties.example`.

## Отдельная работа над одним уроком

Стек курса занимает порты 8000 и 8500, поэтому для изолированного запуска урока
сначала остановите общий:

```bash
docker compose down
cd "Lesson 06/app" && docker compose up -d    # UI :8506, API :8006
```

У каждого урока собственные порты (01 → 8000/8501, 02 → 8002/8502, 03 → 8003/8503,
04 → 8004/8504, 05 → 8005/8505, 06 → 8006/8506, 07 → 8007/8507, 08 → 8008/8508) и собственные тесты:

```bash
cd "Lesson 06/app" && docker compose run --rm api python -m pytest -q
```

## Ограничения

- Потолок вывода — 10 000 токенов на запрос; при обрыве по лимиту UI показывает
  предупреждение, а в таблицах появляется пометка «обрезан».
- Бесплатные тарифы ограничены по числу запросов и могут отвечать `403`/`429` с
  конкретной сети — это не ошибка приложения, индикатор провайдера покажет `🟠`.
