# Урок 04 — Температура

Лаборатория температуры: одна модель, один промпт — разные значения `temperature`.
Задача урока — увидеть своими глазами, что температура делает с ответом: где ответ
обязан быть единственным, а где разнообразие как раз и нужно.

## Быстрый старт

```bash
cd "Lesson 04/app"
cp config/secrets.properties.example config/secrets.properties   # вписать ключ
docker compose up -d --build
```

- UI: http://localhost:8504
- API: http://localhost:8004/docs

Порты переопределяются в `.env` (`API_PORT`, `FRONT_PORT`).

## Что на экране

### Сайдбар — только три ручки

| Ручка | Зачем |
|---|---|
| **Модель** | поповер `⚙ <модель> ▾` со всеми провайдерами: DeepSeek и бесплатные OpenRouter, Nous Portal |
| **Температура** | 0.0…2.0 с шагом 0.1, действует на чат |
| **Max tokens** | 100…10 000, общий предел для чата и для сравнения |

Плюс строка индикаторов доступности: `🟢` отвечает, `🟠` ключ есть но провайдер не
отвечает, `⚪` ключа нет — например `🟢 DeepSeek ⚪ Gemini 🟠 OpenRouter`.

### Основное окно

1. **Чат** — обычный диалог с моделью; в мете видно температуру, время и токены,
   при обрыве по лимиту появляется предупреждение.
2. **Пять кнопок — это типы задач**, а не отдельные промпты. Внутри каждого типа
   выпадающий список «Сложность» с тремя вариантами `low` / `medium` / `high`:

| Кнопка (тип) | `low` | `medium` | `high` |
|---|---|---|---|
| **Точный ответ** | 17 × 4 → 68 | 23 × 17 → 391 | (48 ÷ 6) × (125 − 117) + 39 → 103 |
| **Логическая задача** | корзина с фруктами → 12 | поезд с задержкой → 18:50, 255 мин | склад и проценты → 45 коробок |
| **Генерация текста** | одно предложение о прогулках | абзац 3–4 предложения | три абзаца со структурой |
| **Варианты названий** | 3 названия кофейни | 5 названий | 7 названий в заданных стилях |
| **Головоломка** | 9 монет → 2 взвешивания | 12 монет → 3 взвешивания | мост с фонариком → 17 минут |

   Сложность показывается только у значений этого списка; кнопка — просто тип задачи.
   Выбор варианта подставляет его текст в поле «Промпт» (его можно править).

3. **Сравнение температур** — три значения (по умолчанию **0, 0.7 и 1.2**) и поле
   **«Количество повторений»** (0…10). Кнопка «Сравнить температуры» прогоняет промпт
   при каждом значении: `0` — по одному запросу на температуру, `N` — ещё N независимых
   повторов (итого `(N + 1) × число температур` запросов, подпись показывает счётчик).
   Каждый повтор — отдельный вызов модели, ответы не переиспользуются.

   Результат — таблица «Температура · Повтор · Ответ · Токены · Время · Лимит».

Под таблицей — сводка: сколько ответов получилось разными (`разных ответов: 3 из 3`)
и разброс длины в символах, плюс устойчивость каждой температуры отдельно —
`t=0.0: 1 из 3 · t=1.2: 3 из 3` (сколько разных ответов дали повторы одной
температуры). Если все ответы совпали, UI так и пишет, что на этой задаче
температура почти не влияет.

4. **Анализ ответов разных температур** — отдельный блок под таблицей: выбираете
   модель-аналитик (можно другую, не ту, что отвечала) и нажимаете
   «Проанализировать ответы». Модель получает промпт, эталон (если он есть) и все
   ответы с номерами повторов, а возвращает разбор: что изменилось между
   температурами, **насколько устойчива каждая температура** (совпадают ли повторы
   между собой и что именно меняется от повтора к повтору), какой ответ лучше, где
   ошибки и какую температуру брать для такой задачи.

Если `/models` провайдера недоступен (сеть, гео-блок, `403`), уроки используют
запасной список бесплатных моделей OpenRouter:
`nvidia/nemotron-3.5-lightning:free`, `nvidia/nemotron-3-ultra-550b-a55b:free`,
`google/gemma-4-31b-it:free`. Живой список
из `/models` важнее: как только провайдер отвечает, каталог строится по нему.

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/health` | статус, провайдер, число задач, прочитанные конфиг-файлы |
| GET | `/api/models` | модели и их возможности (`provider`, reasoning-уровни) |
| GET | `/api/tasks` | пять типов задач, у каждой три варианта `low/medium/high` с эталоном и подсказкой |
| GET | `/api/providers/status` | доступность провайдеров (кеш 60 с) |
| POST | `/api/models/refresh` | перечитать бесплатные модели без рестарта |
| POST | `/api/chat` | `text/event-stream`: `start` → `reasoning`/`delta` → `done` |
| POST | `/api/temperature/compare` | по одному запросу на температуру плюс `repeats` повторов, со `spread.per_temperature` |
| POST | `/api/analyze` | модель-аналитик разбирает ответы при разных температурах |

Пример сравнения:

```bash
curl -X POST http://localhost:8004/api/temperature/compare \
  -H 'Content-Type: application/json' \
  -d '{"model": "deepseek-flash", "prompt": "Придумай 5 названий для кофейни у парка",
       "temperatures": [0, 0.7, 1.2], "repeats": 2, "max_tokens": 800}'
```

Ответ:

```json
{
  "model": "deepseek-flash",
  "runs": [
    {"temperature": 0.0, "repeat": 0, "answer": "…", "usage": {"completion_tokens": 84}},
    {"temperature": 0.0, "repeat": 1, "answer": "…", "usage": {"completion_tokens": 86}},
    {"temperature": 1.2, "repeat": 0, "answer": "…", "usage": {"completion_tokens": 88}},
    {"temperature": 1.2, "repeat": 1, "answer": "…", "usage": {"completion_tokens": 91}}
  ],
  "spread": {"unique_answers": 3, "answers": 4, "min_length": 240, "max_length": 320,
             "errors": 0, "truncated": 0, "repeats": 1,
             "per_temperature": {"0.0": {"runs": 2, "unique": 1},
                                 "1.2": {"runs": 2, "unique": 2}}}
}
```

Дубли температур схлопываются, значения вне `0…2` отклоняются с `422`.

## Бесплатные провайдеры

Как и в прошлых уроках: `gemini.api.key`, `openrouter.api.key`, `nous.api.key`
в `config/secrets.properties`. Список моделей читается из `/models` провайдера
при старте (до трёх подходящих на провайдера), `POST /api/models/refresh`
перечитывает без перезапуска.

Если `/models` недоступен (сеть, гео-блок, `403`), используется запасной список:
OpenRouter — `nemotron-3.5-lightning`, `nemotron-3-ultra`, `gemma-4-31b`;
Nous Portal — `step-3.7-flash`, `solar-mini4`, `longcat-2.5`, `beam-1.0-501b`. Живой
список всегда важнее запасного.

## Один интерфейс для четырёх уроков

Фронт урока 04 — это и есть общий UI курса: в сайдбаре переключатель раздела
«Чат (урок 01)» / «Форматы ответа (урок 02)» / «Способы рассуждений (урок 03)» /
**«Температура (урок 04)»**, а выбор модели во всех разделах — один и тот же
поповер `⚙ <модель> ▾`.

В корневом стеке всё открывается с одного адреса: UI на `http://localhost:8500`,
API урока — `http://localhost:8000/lesson-04/api/...` (шлюз разводит уроки по
префиксам). Изолированно этот урок занимает 8004/8504. Адреса остальных API
задаются переменными `CHAT_API_BASE_URL`, `FORMAT_API_BASE_URL`,
`REASONING_API_BASE_URL`, собственный API — `TEMP_API_BASE_URL`.

## Обрыв по лимиту токенов

Если ответ не уместился в `max_tokens`, в чате появляется предупреждение, а в
таблице сравнения — пометка «обрезан». Mock-провайдер режет ответ по бюджету и
возвращает `finish_reason=length`, поэтому предупреждение можно проверить офлайн.

## Что важно понять из урока

- Температура не «улучшает» модель — она меняет разброс. Для задач с единственным
  ответом это риск, для генерации текста и названий — источник вариантов.
- `temperature=0` не гарантирует побитово одинаковый ответ, но делает его заметно
  стабильнее: на арифметике и логике это видно сразу.
- Сравнивать температуры честно можно только при одинаковых модели, промпте и
  `max_tokens` — иначе разница в ответе может быть вызвана не температурой.
