# Урок 12 · Персонализация ассистента

## Цель

Сделать ассистента персональным: хранить профиль и предпочтения пользователя,
подключать их к каждому запросу и пополнять профиль из диалога, а не только из
ручной формы.

## Четыре части урока

1. **Профиль пользователя**
   - имя, роль, город, язык, часовой пояс;
   - SQLite `profiles`, изоляция по `owner_id`;
   - история изменений с источником.

2. **Предпочтения**
   - `style` — формальный / неформальный стиль;
   - `format` — формат ответа;
   - `code_examples` — с примерами кода / без примеров кода;
   - `emoji` — с emoji / без emoji;
   - `constraints` — ограничения;
   - SQLite `preferences`, source и confidence.

3. **Профиль в каждом запросе**
   - система prompt всегда содержит профиль и предпочтения;
   - незаполненные поля явно помечаются;
   - профиль — данные, а не инструкции;
   - API возвращает фактический `system_prompt` и токены.

4. **Автообогащение из диалога**
   - из реплики извлекаются имя, роль, город, стиль, формат, примеры кода, emoji и ограничения;
   - изменения сразу сохраняются с `source="диалог"`;
   - ответ API содержит `updates`, поэтому UI показывает, что обновилось.

## API

- `GET /api/health`
- `GET /api/profile`
- `POST /api/profile`
- `POST /api/preferences`
- `DELETE /api/preferences/{key}`
- `GET /api/context`
- `POST /api/chat`
- `POST /api/chat/reset`
- `POST /api/profile-check/question` — новый вопрос без кеша;
- `POST /api/profile-check/all` — один вопрос всем профилям;
- `POST /api/profile-check/batch` — 10 случайных вопросов разным профилям;
- `POST /api/profile-check/analyze` — анализ моделью `deepseek-v4-pro`.

## UI

В общем интерфейсе — раздел **«Персонализация ассистента (урок 12)»**:

- **Чат с профилем** — первая вкладка;
- **Профиль** — имя, роль, город, язык, часовой пояс;
- **Предпочтения** — стиль, формат, примеры кода, emoji, ограничения;
- **Контекст** — фактический system prompt;
- **Проверка профилей** — уникальный вопрос всем профилям и 10 случайных вопросов
  разным профилям; после 10 ответов доступен анализ результатов моделью
  `deepseek-v4-pro` из OpenCode Go. Темы серии подбираются под специализацию
  профиля; в system prompt есть правило не выходить за границы роли.
  Ответы дописываются при обрыве, а профиль с «с примерами кода» получает
  обязательный релевантный блок кода. Лимит ответа — 1600 токенов, ответы
  запрашиваются компактными. Аудит считает соблюдение предпочтений, номер первого
  нарушения и устойчивость профилей после 10 вопросов.

В сайдбаре — переключатель текущего профиля и удаление с подтверждением. Пять
профилей: базовый `demo` и четыре тестовых — `test-alice`, `test-elena`,
`test-ivan`, `test-olga`. Вопросы проверки генерируются на сервере, не кешируются и
имеют уникальный `question_id`; для каждой сессии создаётся свой `session_id`.
