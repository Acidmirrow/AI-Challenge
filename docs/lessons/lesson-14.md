# Урок 14 · Инварианты и ограничения состояния

## Цель

Показать, как ассистент работает в рамках явных ограничений проекта:
инварианты хранятся отдельно от диалога, проверяются кодом до выдачи ответа,
а изменение возможно только явной командой с записью в историю.

## Инварианты

- `INV-001` — архитектура: только HTTP REST или асинхронные события, без
  прямых синхронных вызовов и общей памяти.
- `INV-002` — стек: Python 3.12, FastAPI, Streamlit, SQLite; никаких
  PostgreSQL, MySQL, MongoDB, Redis, Kafka, RabbitMQ и новых фреймворков.
- `INV-003` — хранение: локальная SQLite, без S3 и внешних файловых хранилищ.
- `INV-004` — секреты: не в коде, git или чате.
- `INV-005` — границы MVP: нельзя добавлять/обещать функции без явного
  решения об объёме.

## Механика

1. `check_text()` проверяет сообщение пользователя кодом. При нарушении
   модель не вызывается, возвращается отказ с ID инварианта и причиной.
2. Модель получает системный промпт с инвариантами и возвращает JSON
   `decision`, `invariants_considered`, `reasoning`, `answer`.
3. Ответ модели повторно проверяется кодом; нарушение заменяется отказом.

Инварианты и история изменений находятся в SQLite, отдельно от
`chat_message`. Изменение выполняется только командой
`!invariant <ID> => <новый текст>` через панель управления; обычный чат
изменить инвариант не может.

## Проверка обхода

`POST /api/bypass-test` запускает 9 формулировок: 8 базовых векторов
(исключение, пример, «забудь ограничения», ролевая подмена, прямой вызов,
hardcode секрета, функция вне MVP, Kafka) и отдельный найденный обход через
управляемую облачную БД. Каждая попытка записывается в `attempt`; UI
показывает `всего`, `заблокировано`, `прошло`. В демо найденный обход
намеренно не исправлен: 8 блокируются, 1 проходит (`escaped = 1`).

- Общий интерфейс: раздел **«Инварианты и ограничения состояния (урок 14)»**.
- Изолированный фронт: `http://localhost:8514`.
- Вкладки: проверка ассистента, обход инвариантов (9 попыток), управление инвариантами.
- В сайдбаре — очистка истории чата и попыток.

## API

`GET /api/health`, `GET /api/invariants`,
`POST /api/invariants/change`, `GET /api/invariants/history`,
`POST /api/chat`, `GET /api/chat/history`, `POST /api/bypass-test`,
`GET /api/attempts`, `POST /api/clear`.
