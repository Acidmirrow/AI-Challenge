# Урок 05 — сравнение моделей

Одна задача или сразу все пять: три модели разного размера отвечают параллельно.
Рядом с каждым ответом — время, токены и стоимость; в режиме «Сравнение по задачам»
ответы сверяются с эталоном, и видно, сколько задач решила каждая модель, во сколько
раз флагман дороже маленькой и на каких задачах маленькой достаточно.

```bash
cd "Lesson 05/app" && docker compose up -d --build
open http://localhost:8505        # UI
curl http://localhost:8005/api/health
```

## Что внутри

| Вкладка / ручка | Что делает |
|---|---|
| Сайдбар | модель, температура, `Max tokens`, reasoning, системный промпт |
| Вкладка «Чат» | обычный чат: все настройки берутся из сайдбара |
| Вкладка «Сравнение моделей» | одна задача или «Все задачи сразу» → три модели (маленькая / побольше / большая); для всех задач — сводка «модель × правильно/неправильно» и «Анализ результатов» |
| Вкладка «Сравнение по задачам» | все пять задач на трёх моделях, проверка по эталону, сводка и вывод |
| Сравнительная таблица | время, токены входа и выхода, всего токенов, стоимость в долларах |
| «Анализ результатов» | выбранная продвинутая модель читает ответы и метрики, сверяет с эталоном |

## Задачи

Пять задач, по одной на уровень сложности — от `low` до `expert`:

| id | Сложность | Тема | Эталон |
|---|---|---|---|
| `arithmetic` | low | 17 × 4 | 68 |
| `fruits` | medium | корзина с фруктами | 12 фруктов |
| `train` | high | поезд с задержкой | 18:50, 255 минут |
| `warehouse` | very high | склад и проценты | 45 коробок |
| `bridge` | expert | мост с фонариком | 17 минут |

Задача и её эталон уходят в запрос сравнения, поэтому модель-аналитик проверяет
ответы не «на глаз», а по эталону.

## Три слота моделей

Каждая модель в каталоге помечена размером — `small`, `medium`, `large`:

- у известных моделей размер задан в каталоге (`deepseek-flash` → small,
  `deepseek-v4-pro` → large);
- у бесплатных провайдеров размер выводится из имени: `…-8b-…` → small,
  `…-27b-…`/`…-31b-…` → medium, `…-120b-…`/`…-550b-…` → large;
- если моделей какого-то размера в каталоге нет, слот показывает весь каталог
  и пишет об этом подписью.

## Параллельность

`POST /api/compare` принимает промпт и 2–3 модели, запускает их через
`asyncio.gather` и возвращает ответы в порядке запроса. Общее время в итогах —
самое долгое ожидание, а не сумма: модели отвечают одновременно.

## Стоимость

`POST /api/compare` считает цену по прайсу `$ за 1 млн токенов`:

- `deepseek-flash`, `deepseek-v4-pro` — из `config/pricing.properties`
  (файл в git, правится без перезапуска кода — читается при старте API);
- `openrouter`, `gemini`, `nous`, `mock` — всегда `0` с пометкой
  «бесплатный провайдер»;
- неизвестная модель — `0` с пометкой «цена не задана».

В таблице видно и цену за миллион, и стоимость конкретного прогона.

## Бенчмарк по всем задачам

`POST /api/benchmark` прогоняет все пять задач на 2–3 моделях: задачи идут по
очереди, модели внутри задачи — параллельно. Для каждого прогона сохраняются
ответ, время, токены и стоимость.

Верность считается по эталону: в ответе должны быть все числа эталона
(`18:50, 255 минут` требует оба значения, `68` не засчитывается за `168`).
Дополнительно можно передать `judge` — модель-судью, которая проверяет итоговый
ответ каждой модели и перекрывает детерминированную проверку; если судья
недоступен или вернул не JSON, остаётся проверка по числам.

Ответ содержит:

- `models[]` — по модели: `correct / total`, `accuracy`, суммарное и среднее
  время, токены, стоимость, число ошибок;
- `comparison` — маленькая и большая модели: `cost_ratio` (во сколько раз
  флагман дороже), `accuracy_delta_pp` (разница точности в п.п.),
  `extra_correct` (на сколько задач больше), `time_ratio`;
- `runs[]` — матрица «задача × модель» с ответом и флагом `correct`.

В UI это таблица «модель → верных / время / токены / стоимость», строка
сравнения флагмана с маленькой моделью, матрица по задачам и блок «Вывод: где
маленькой модели достаточно» — вывод делает выбранная модель-аналитик
(`POST /api/benchmark/analyze`).

## API

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/health` | статус, провайдер, число задач |
| `GET` | `/api/tasks` | пять задач с эталонами |
| `GET` | `/api/models` | каталог моделей с полем `tier` |
| `POST` | `/api/models/refresh` | перечитать модели бесплатных провайдеров |
| `GET` | `/api/providers/status` | доступность провайдеров |
| `POST` | `/api/chat` | чат (SSE-стриминг) |
| `POST` | `/api/compare` | один промпт на 2–3 модели параллельно |
| `POST` | `/api/analyze` | анализ сравнения продвинутой моделью |
| `POST` | `/api/benchmark` | все задачи на 2–3 моделях: верные ответы, время, токены, цена |
| `POST` | `/api/benchmark/analyze` | вывод: где маленькой модели достаточно |

## Конфигурация

- `config/app.properties` — провайдер, лимиты, `pricing.file`, в git;
- `config/pricing.properties` — прайс моделей, в git (секретов нет);
- `config/secrets.properties` — ключи, gitignored, монтируется при деплое.

анализ, чат, расчёт стоимости, итоговые токены, бесплатные модели Nous Portal
на все три размера, проверка ответов по эталону (числа и время), бенчмарк
с судьёй и его fallback на детерминированную проверку.
