# Урок 15 · Устаревание и конфликты памяти

## Цель

Показать память, которая обновляется при изменении данных: конфликтующий
факт заменяет старое значение, замена фиксируется в истории, а рабочая
память очищается после завершения задачи.

## Правила

- `replace`: `deadline`, `status`, `version`, `approach`, `sms_requirement`.
- `append`: `decisions`, `change_history`.
- `delete_on_complete`: краткосрочная и рабочая память.
- Каждый факт хранит `created_at` и `updated_at`.
- В промпт попадают только актуальные значения; `fact_history` остаётся в
  хранилище для аудита.

## Конфликты

`MemoryStore.update()` заменяет значение по ключу, пишет старую и новую
версию в `fact_history` и обновляет время записи. Для списков
(`decisions`, `change_history`) значение накапливается, а не теряется.

## Проверка

Сценарий меняет 5 фактов и добавляет 2 решения, проверяет дубликат и
провоцирует агента назвать старое значение. После каждого шага агент
отвечает на вопрос; API считает:

- `stale_answers` — сколько ответов содержали старое значение;
- `stale_mentions` — сколько старых значений упомянуто;
- `old_values_in_prompt` — сколько старых значений попало в промпт.

В демо все три метрики равны 0.

## Очистка

`POST /api/task/complete` очищает `working` и `short_term`; таблица `fact`
сохраняется. UI показывает количество очищенных записей и сохранённых фактов.

## UI и API

- UI: `http://localhost:8515`; общий интерфейс — раздел
  **«Устаревание и конфликты памяти (урок 15)»**.
- Разделы: «Проверка памяти», «Сценарий конфликтов», «Сценарии добавления» (append), «Тестовый диалог» (видны действия перезаписи/добавления), «Правила и очистка».
- API: `/api/state`, `/api/policies`, `/api/prompt`, `/api/chat`,
  `/api/task/start`, `/api/task/complete`, `/api/scenario`, `/api/audits`,
  `/api/reset`.
- Общий стек: `/lesson-15/api/*`.
