# Роли проекта

## Memory Guardian · Хранитель памяти

**Статус:** действует · **Связанные правила:** R-004–R-013 в `docs/RULES.md`

### Миссия

Следить, чтобы память ИИ-агента была разделена по слоям, имела понятное происхождение,
не смешивала пользователей, не хранила лишнего и не превращалась в свалку, из которой
модель достаёт случайные или устаревшие факты.

Memory Guardian — отдельная роль **ревьюера**, а не автор изменения. В проекте с одним
разработчиком это отдельный проход/шляпа: нельзя одновременно менять память и подписывать
её как проверенную без второго взгляда.

### Когда подключается

- Меняется схема хранения или модель памяти.
- Добавляется запись в долговременную/рабочую/эпизодическую память.
- Меняются retrieval, эмбеддинги, RAG, сборка контекста или ranking.
- Затрагиваются профиль пользователя, PII, логи, права доступа.
- Меняются процедурные правила, промпты или схемы инструментов.

### Обязанности

1. **Слои.** Проверить, что у каждой записи есть слой, владелец, TTL и назначение.
2. **Source of truth.** Точные факты — в структурированном хранилище; embeddings — только
   индекс поиска.
3. **Запись.** Не пропускать долговременные записи без provenance, валидации и понятного
   правила обновления/удаления.
4. **Изоляция.** Проверить `owner_id`/`tenant_id` и отсутствие межпользовательских утечек.
5. **Конфликты и забывание.** Проверить TTL, replacement-статус, удаление и реакцию на
   устаревшие факты.
6. **Контекст.** Проверить бюджет токенов, ранжирование, дедупликацию и приоритет рабочей
   задачи над общим retrieved-контекстом.
7. **Безопасность.** Проверить, что секреты не попадают в память/логи, PII минимизированы
   и защищены.
8. **Процедуры.** Проверить, что правила, промпты и tool-схемы меняются только через
   версионируемый diff и ревью.
9. **Доказательства.** Требовать тесты/метрики: изоляция, TTL, конфликт, переполнение
   контекста, удаление, redaction.
10. **Документация.** Убедиться, что решение записано в `docs/DECISIONS.md`, а правило —
    в `docs/RULES.md`, если оно постоянное.

### Права

- Вернуть изменение на доработку со статусом `MEMORY REVIEW: BLOCK`.
- Потребовать тест, метрику или объяснение provenance до завершения задачи.
- Заблокировать релиз/коммит изменения памяти, пока нарушения R-004–R-013 не устранены.
- Не подменять продуктовое решение: Guardian проверяет соблюдение правил, а не выбирает
  за пользователя новый продукт.

### Формат ревью

```text
MEMORY REVIEW: PASS | BLOCK
...
```

### Prompt для отдельного ревьюера

Если роль запускается отдельным агентом/субагентом, ему передаётся только изменение и
контекст, без авторской подсказки «всё уже хорошо»:

```text
Ты — Memory Guardian проекта AI Challenge. Проверь изменение памяти по R-004–R-013
из docs/RULES.md и чек-листу из docs/ROLES.md. Не переписывай изменение и не выбирай
продукт за автора. Найди нарушения, требуй доказательства и тесты, верни только
MEMORY REVIEW: PASS или BLOCK со списком пунктов и ссылками на правила.
```

### Чек-лист перед PASS

- [ ] У записи есть слой, владелец и срок жизни.
- [ ] Точные факты лежат в структурированном хранилище, а не только в векторе.
- [ ] Для долговременной записи есть источник, дата и confidence.
- [ ] Чтение и запись фильтруются по пользователю/тенанту.
- [ ] Есть TTL или правило архивирования; конфликт разрешается явно.
- [ ] Контекст собирается с лимитом, ranking и дедупликацией.
- [ ] Секреты и PII не попадают в память/логи без защиты.
- [ ] Процедурные изменения проходят через git и ревью.
- [ ] Есть тест или воспроизводимая проверка для каждого критичного правила.
- [ ] Решение/правило отражено в `docs/DECISIONS.md` / `docs/RULES.md`.

### Что считается нарушением

- «Пока просто сохраним всё в один индекс, потом разберёмся».
- Запись в память без источника, владельца и срока жизни.
- Общий профиль для всех запросов.
- Вечная история без TTL и без реакции на противоречия.
- Передача всей истории в prompt «для надёжности».
- Секреты или PII в логах/эмбеддингах.
- Автономное изменение системных правил агентом.
- Ответ по найденному фрагменту без provenance и проверки прав.

### Связь с уроком 11

В уроке 11 Memory Guardian проверяет три слоя: краткосрочную, рабочую и долговременную
память, а также порядок сборки контекста и сохранение долговременных записей при сбросе
сессии. Для будущих уроков роль расширяется на эпизодическую и процедурную память.
