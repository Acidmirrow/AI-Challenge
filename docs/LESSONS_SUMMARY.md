# AI Challenge — краткое summary уроков

Актуально: уроки 01–18. Это сжатая карта проекта: вместо чтения всех README и
исходников достаточно этого файла, а детали — по ссылкам ниже.

## Архитектура

- Каждый урок — отдельное приложение FastAPI + Streamlit в `Lesson 0X/app/`.
- Общий стек: UI `http://localhost:8500`, шлюз `http://localhost:8000` с
  маршрутами `/lesson-01/api/*` … `/lesson-18/api/*`. Разделы UI сгруппированы
  по 5 уроков: 01–05 — неделя 1, 06–10 — неделя 2, 11–15 — неделя 3 (пройдена),
  16–20 — неделя 4 (текущая), 21–25 — неделя 5; стартует последний урок, будущие недели показывают заглушку.
- Общий фронт собирается из `shared_front/`; изолированные порты:
  01 → 8000/8501, 02 → 8002/8502, 03 → 8003/8503, 04 → 8004/8504,
  05 → 8005/8505, 06 → 8006/8506, 07 → 8007/8507, 08 → 8008/8508,
  09 → 8009/8509, 10 → 8010/8510, 11 → 8011/8511, 12 → 8012/8512, 13 → 8013/8513, 14 → 8014/8514, 15 → 8015/8515, 16 → 8016/8516, 17 → 8017/8517, 18 → 8018/8518.
- Провайдеры: OpenCode Go (основной; `deepseek-v4.1-flash` для чата и
  `deepseek-v4-pro` для анализа), бесплатные OpenRouter и Nous Portal; прямой DeepSeek
  остаётся альтернативой, Gemini есть в API, но скрыт во фронте.
  Ключи — в gitignored `Lesson 0X/app/config/secrets.properties`.
- Уроки 01–07 используют общий выбор модели в сайдбаре; бесплатные модели
  фильтруются по `:free` и стоимости 0.

## Урок 07 подробнее

- Контекст хранится в SQLite `Lesson 07/app/data/context.db`; таблицы `sessions`
  и `messages`. В истории сохраняются реплики, `tool_calls`, имена инструментов
  и наблюдения `role=tool`.
- После очистки пустая сессия не считается диалогом; счётчик показывает только
  диалоги с сообщениями.
- В сайдбаре есть удаление всех контекстов из SQLite (с подтверждением).
- При открытии раздела загружается последняя обновлённая сессия со всей историей.
- Сессии выбираются из выпадающего списка: «Диалог N · тема · сообщений»;
  номер обеспечивает уникальность, ID хранится в URL (`?session=...`).
- `session_id` хранится в URL (`?session=...`), поэтому после перезагрузки
  страницы открывается тот же диалог; в сайдбаре можно создать новую сессию,
  очистить историю или удалить её.
- Перед запросом API собирает окно из последних сообщений (2–500 в UI, по
  умолчанию 20) и ограничивает его 20 000 символов; старые сообщения отбрасываются.
- В сайдбаре можно отметить несколько прошлых бесед или включить «Все прошлые
  сессии»: их сообщения и tool calls подмешиваются в контекст текущего запроса.
  Если в запросе явно указано «Диалог N», его история подключается автоматически;
  фраза «из разных сессий» подключает весь архив.
- API: `POST /api/chat`, `GET /api/tools`, `GET /api/sessions`,
  `GET /api/sessions/{id}`, `DELETE /api/sessions` (все),
  `DELETE /api/sessions/{id}` (одна), `POST /api/sessions/{id}/clear`.
- Инструменты — те же 9, что в уроке 06 (`agent_tools.py`); агент продолжает
  диалог с загруженной историей, включая прошлые вызовы инструментов.
- UI: вверху справа компактные показатели (сообщения, сессия, модель,
  диалоги), сообщения compact, метки «💾 сохранено», итог с действиями.
- Код: `Lesson 07/app/api/app/storage.py`, `context.py`, `agent.py`; UI —
  `Lesson 07/app/front/context_page.py`.

## Урок 08 подробнее

- API считает символы, слова, токены и отношение токенов к словам/символам.
- Модели: DeepSeek Flash/Pro (контекст 1M) и mock (32K); резерв под ответ
  вычитается из контекстного окна.
- Если текст не помещается, API возвращает превышение и обрезанный по границе
  токена вариант.
- Стоимость: вход по фактическим (помещающимся) токенам + максимальный резерв ответа;
  тарифы DeepSeek из урока 05, mock — бесплатный.
- Сравнение строит три контекста: базовый, ~70% доступного бюджета и ~120%
  с превышением; показывает токены, стоимость, обрезку и зависимости.
- Симуляция диалога показывает, как каждый следующий ход заново отправляет
  историю, как растёт prompt-токены и накопленная стоимость; при переполнении
  перечисляются риски (обрезка system/tool call, потеря фактов, отказ провайдера).
- Токенизация учебная regex-аппроксимация; точный расход — в `usage` модели.
- Код: `Lesson 08/app/api/app/tokenizer.py`, `models.py`; UI —
  `Lesson 08/app/front/token_page.py`.

## Урок 09 подробнее

- Кнопка **«Сформировать диалог»** в сайдбаре создаёт 25 сообщений
  (12 пар и завершающая реплика) о вымышленном проекте «Ласточка»: адрес,

- Данные не вызывают модель и не сохраняются в базу: это воспроизводимый

- В блоке «Сжатие истории»: лимит сообщений, окно токенов и резерв под ответ;
  выбора стратегии нет. Для каждого сообщения видна метка «в контексте / отброшено».
- Диалог — 25 сообщений: блоки 10, 10 и 5; summary каждого блока хранятся
  отдельно, не в списке сообщений. UI не кэширует диалог: при каждом
  перерасчёте он запрашивается заново, вопрос уходит с новым контекстом.
- Кнопка «Сжать контекст (summary)» подставляет summary вместо полной истории;
  повторное нажатие возвращает сообщения.
- Вкладка «Сравнение токенов» показывает таблицу: полная история vs summary,
  токены, экономия и попадание в окно.
- Внизу — чат по истории: вопрос ищется только в выбранной части контекста,
  ответ содержит источник `№`; если факт отброшен, ответ объясняет, какие
  сообщения попали в контекст и какие отброшены.
- Стратегии: `budget` (последние сообщения в пределах лимита и токенов),
  `last` (ровно N последних), `full` (вся история, включая переполнение).
- `available` — бюджет после резерва; `message_budget` — остаток на сообщения
  после системной части. При превышении API возвращает `overflow` и `fits=false`.
- API: `GET /api/health`, `GET /api/demo-dialogue`, `POST /api/context`,
  `POST /api/ask`, `POST /api/compress`.
- Код: `Lesson 09/app/api/app/dialogue.py`, `context.py`; UI —
  `Lesson 09/app/front/control_page.py`.

## Ключевые решения

- Общая архитектура «урок = приложение»: копипаста между уроками осознанная,
  общий стек только собирает их за одним адресом.
- Все секреты — только в gitignored properties/`.env`; в git едут `*.example`.
- Nous Portal подключается напрямую по ключу или через локальный `hermes proxy`
  (loopback + `Host`-заголовок); бесплатны только модели с `:free`.
- В уроке 06 проверка нехватки инструмента детерминированная (по типу задачи),
  плюс страховка, если модель сама попросит недоступный инструмент.

## Урок 13 подробнее

- Отдельный пункт меню **«Состояние задачи (Task state machine) (урок 13)»** в неделе 3.
- Формальный автомат: `planning → execution → validation → done`; действия `submit_plan`, `approve_plan`, `start_execution`, `complete_execution`, `start_validation`, `pass_validation`, `fail_validation`, `finish`, `rework`, `pause`, `resume`.
- Guards проверяются кодом до изменения состояния; запрещены перепрыгивание этапов, завершение без валидации и мутации на паузе; `rework` сбрасывает флаги реализации и валидации.
- SQLite `Lesson 13/app/data/lesson13.db`: `task`, `task_history`, `task_step`, `chat_message`, `agent_log`; версия состояния, история отказов и персистентный чат.
- Весь диалог и постановка — через чат: `/gotask <цель>`; уточняющие вопросы выделяются, план формируется после ответов и скрыт в expander.
- `/approve` запускает 10-секундный отсчёт, затем реализацию; шаги выполняются автоматически без `/step`, результаты — в отдельных свёрнутых expander.
- После последнего шага — интерактивный 10-секундный отсчёт и автостарт валидации; ожидается `/pass` или `/fail`; `/pass` сразу переводит в «Готово», `/finish` не нужен.
- Ошибки шагов содержат причину, `hint` и `details.llm_code`; в сайдбаре — очистка задач и чата с подтверждением.
- Изолированный запуск: API `8013`, UI `8513`; в общем стеке — `/lesson-13/api/*`.
- Тесты: **29 passed**.

## Урок 15 подробнее

- Долговременная память: `deadline`, `status`, `version`, `approach`, `sms_requirement` — перезапись; `decisions`, `change_history` — накопление списком.
- У каждого факта есть `created_at`/`updated_at`; конфликтующее значение заменяет старое по ключу, а не создаёт вторую запись.
- Замена фиксируется в `fact_history` с `old_value`, `new_value`, типом изменения, причиной и временем; в промпт попадают только актуальные значения.

## Урок 18 подробнее

- Фоновый `asyncio`-планировщик стартует вместе с API: снимок каждые 10 секунд, отчёт каждые 30 секунд, окно отчёта 60 минут.
- MCP-сервер `lesson18-scheduler` предоставляет `fetch_metrics`, `save_snapshot` и `read_snapshots`; сохранение и чтение идут через SQLite.
- Каждый запуск — отдельная запись `snapshots` с `run_id`; отчёт агрегирует все снимки периода: `runs`, `snapshot_ids`, суммы запросов/ошибок, средние CPU/задержки и `series`.

- Данные сохраняются в `Lesson 18/app/data/lesson18.db` и переживают перезапуск контейнера.
- Лимит — 500 снимков; при превышении удаляется самый ранний. Кнопка «Очистить результаты» удаляет все снимки и отчёты.
- Изолированный запуск: API `8018`, UI `8518`; тесты: **9 passed**.
