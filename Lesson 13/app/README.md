# Урок 13 — Состояние задачи (Task state machine)

Отдельное FastAPI + Streamlit-приложение с формальным жизненным циклом задачи:

```text
planning → execution → validation → done
```

Переходы проверяет сервер до изменения состояния. LLM и UI не могут обойти
guard: чат видит снимок состояния, но не меняет его; команды чата вызывают
только разрешённые действия.

## Что реализовано

- создание задачи с целью командой `/gotask <цель>`; план формируется в чате после ответов на уточняющие вопросы;
- этапы `planning`, `execution`, `validation`, `done`;
- текущий шаг и ожидаемое действие;
- действия `submit_plan`, `approve_plan`, `start_execution`,
  `complete_execution`, `start_validation`, `pass_validation`,
  `fail_validation`, `finish`, `rework`, `pause`, `resume`;
- guard-условия и запрет перепрыгивания этапов;
- сброс флагов реализации и валидации при `rework`;
- пауза и продолжение без потери этапа и контекста;
- версия состояния и оптимистичная блокировка;
- история успешных переходов и отказов;
- отдельный чат, который получает снимок задачи, но не мутирует его;
- визуализация stepper в UI: пройденные, текущий, будущие этапы, пауза,
  прогресс и флаги.

## Правила жизненного цикла

| Действие | Этап | Условие |
|---|---|---|
| `submit_plan` | planning | план не пуст |
| `approve_plan` | planning | план сохранён |
| `start_execution` | planning | план утверждён |
| `complete_execution` | execution | реализация ещё не завершена |
| `start_validation` | execution | реализация завершена |
| `pass_validation` | validation | решение ещё не принято |
| `fail_validation` | validation | решение ещё не принято |
| `finish` | validation | валидация пройдена |
| `rework` | validation | валидация провалена |
| `pause` | planning / execution / validation | задача активна |
| `resume` | тот же этап | задача на паузе |

Запрещены `planning → validation`, `planning → done`, `execution → done`,
`validation → planning` и любые переходы из `done`. При паузе разрешён только
`resume`.

## API

Все запросы к задаче требуют заголовок `X-Session-Id`. Ответы отдаются с
`Cache-Control: no-store`.

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/health` | состояние сервиса |
| `POST` | `/api/task` | создать задачу |
| `POST` | `/api/task/clarify` | уточняющие вопросы в чате или план после ответов |
| `GET` | `/api/task` | получить текущую задачу |
| `POST` | `/api/task/transition` | применить действие |
| `POST` | `/api/task/pause` | поставить на паузу |
| `POST` | `/api/task/resume` | продолжить |
| `GET` | `/api/task/history` | история переходов и отказов |
| `GET` | `/api/task/log` | журнал работы агента |
| `GET` | `/api/task/steps` | шаги реализации и прогресс |
| `POST` | `/api/task/step` | выполнить следующий шаг плана |
| `POST` | `/api/chat` | чат по текущей задаче |
| `GET` | `/api/chat/history` | история чата текущей задачи |
| `POST` | `/api/chat/message` | сохранить сообщение/команду в историю |
| `DELETE` | `/api/task` | очистить задачи, шаги, историю, чат и лог |
| `DELETE` | `/api/chat/history` | очистить только сообщения чата |

Пример перехода:

```json
{
  "action": "start_execution",
  "reason": "План утверждён",
  "version": 3
}
```

При ошибке возвращается структурированный код:
`transition_not_allowed`, `guard_failed`, `task_paused`, `version_conflict`,
`active_task_exists`, `task_not_found`.

## Хранение

SQLite: `Lesson 13/app/data/lesson13.db`.

Таблицы:

- `task` — состояние задачи, флаги и версия;
- `task_history` — append-only история переходов и отказов;
- `task_step` — шаги плана, статусы и результаты;
- `chat_message` — персистентная история чата;
- `agent_log` — запросы, поиск, переходы и ошибки агента.

В Docker-стеке папка `data` подключена как volume, поэтому состояние переживает
перезапуск контейнера.

## UI

Отдельный фронт: `http://localhost:8513`.
В общем интерфейсе — раздел **«Состояние задачи (Task state machine) (урок 13)»**.

На экране:

- одно поле ввода: обычное сообщение — чат, `/gotask <цель>` — постановка задачи;
- отправка сообщения по Enter или кнопке «Отправить»; поле ввода находится под окном чата;
- план передаётся в следующие этапы и по умолчанию скрыт в expander «План задачи»;
- переключатель **«Разрешить агенту интернет»**: результаты поиска передаются модели как факты, без вывода ссылок и списка источников;
- вкладка **«Лог агента»** с запросами, переходами, поиском и ошибками;
- после `/gotask` задача создаётся и сразу получает первый ответ ассистента;
- визуализация появляется только после постановки задачи;
- stepper из четырёх этапов с визуальным статусом;
- текущий шаг, ожидаемое действие, версия;
- флаги плана, реализации и валидации;
- панель «Реализация по плану»: шаги, прогресс и результаты каждого шага в свёрнутых expander;
- управление только командами в чате (`/approve`, `/start`, `/validate`, `/pass`, `/fail`, `/rework`, `/pause`, `/resume`); список всех команд — в одном expander «📋 Все команды чата»;
- пауза и продолжение;
- история переходов и отказов;
- чат по задаче только во вкладке «Состояние задачи»;
- ссылки и URL в ответах ассистента скрываются; 18+ контент не используется;
- вкладка «Лог агента» без чата;
- история чата, запросов и задач сохраняется в SQLite и восстанавливается после обновления страницы;
- в сайдбаре — очистка задач и чата с подтверждением.

Запрещённые переходы не показываются как доступные команды; сервер дополнительно
проверяет каждое действие.

## Модель и reasoning

Для DeepSeek V4.1 используется `reasoning_effort=low`: иначе при небольшом
`max_tokens` весь лимит уходит на reasoning, а `content` приходит пустым и
появляется сообщение «Модель сейчас недоступна». Если content всё равно пуст,
клиент повторяет запрос с увеличенным лимитом.


## Контекст до постановки задачи

Если пользователь описал план или требования в чате до `/gotask`, эти сообщения
передаются планировщику и сохраняются за новой задачей. В новый чат переносятся
сообщения пользователя; старые ответы ассистента не смешиваются с новым состоянием.


## Утверждение плана

Команда утверждения плана `/approve` запускает 10-секундный отсчёт, после
которого состояние переходит в `execution`. Шаги выполняются автоматически,
без `/step`; `complete_execution` и `start_execution` пользователю не нужны.


## Автовыполнение шагов

После перехода в реализацию шаги выполняются автоматически, без `/step`.
Интерфейс показывает прогресс, статус каждого шага и результат. Кнопка
«Остановить автовыполнение» позволяет прервать процесс и затем продолжить.
После последнего шага реализация автоматически завершается, затем UI показывает
интерактивный 10-секундный отсчёт и запускает валидацию. `/complete` и `/step`
не используются.


## Валидация

После реализации запускается валидация; ожидается только решение пользователя:
`/pass` или `/fail`. При `/pass` задача сразу переходит в `done`; отдельная
команда `/finish` не нужна. При `/fail` доступен `/rework`: задача возвращается
в реализацию, шаги сбрасываются в ожидание.


## Шаги и интернет

Если переключатель интернета включён, каждый шаг реализации получает
результаты веб-поиска как факты. Ссылки в ответе и в интерфейсе не показываются.
Поиск не заменяет доступ к приватным Jira/GitHub: без URL и токенов агент
сможет использовать только публичные данные.


## Тестовое задание

Кнопка **«🧪 Тестовое задание: 5 событий 1969 года»** создаёт небольшую
задачу с готовым планом из трёх шагов и оставляет её на этапе планирования
для утверждения. Цель — найти пять значимых событий 1969 года, проверить даты
и кратко объяснить значимость. Задание доступно, когда нет активной задачи.


## Таймер утверждения

После команды утверждения плана запускается явный отсчёт 10 секунд. По его
завершении выполняются `approve_plan` и `start_execution`, затем шаги
выполняются автоматически. Чат отображается до запуска автовыполнения и
остаётся доступным для просмотра.


## Результаты шагов

Каждый шаг в блоке «Реализация по плану» — отдельный свёрнутый expander:
статус в заголовке, рассуждение и результат внутри. Длинные ответы не
растягивают страницу.


## Ошибки шагов

При сбое модели шаг возвращает `step_failed` с `message`, `hint` и
`details.llm_code`. В чате и панели шага показываются причина и рекомендация
(ключ, сеть, квота, пустой ответ, лимит токенов).


## Очистка данных

В сайдбаре урока 13: «🧹 Очистить задачи» удаляет задачи, шаги, историю,
чат и лог; «💬 Очистить чат» удаляет только сообщения. Обе кнопки требуют
подтверждения.
