# Урок 15 — Устаревание и конфликты памяти

Отдельное FastAPI + Streamlit-приложение, в котором память не только
пополняется, но и обновляется: новые значения заменяют старые, конфликт
фиксируется в истории, а рабочая память очищается после завершения задачи.

## Правила долговременной памяти

| Ключ | Факт | Правило | Поведение |
|---|---|---|---|
| `deadline` | Срок | перезапись | новое значение заменяет старое |
| `status` | Статус | перезапись | новый статус заменяет старый |
| `version` | Версия | перезапись | новая версия заменяет старую |
| `approach` | Подход | перезапись | выбранный подход заменяет предыдущий |
| `sms_requirement` | Требование SMS | перезапись | активно / отменено |
| `decisions` | Принятые решения | накопление | новые решения добавляются списком |
| `change_history` | История изменений | накопление | аудит не теряется |

У каждого факта есть `created_at` и `updated_at`. Рабочая память и
краткосрочная память живут до завершения задачи; долговременные факты
сохраняются.

## Разрешение конфликтов

`MemoryStore.update()`:

1. находит факт по ключу;
2. для `replace` заменяет значение, а не создаёт вторую запись;
3. для `append` дописывает элемент к существующему списку;
4. при изменении пишет `fact_history` с `old_value`, `new_value`, причиной и
   временем;
5. обновляет `updated_at`.

В промпт попадает только `prompt_block()` с текущими значениями; `change_history`
(аудит «было → стало») в промпт не включается; API `/api/prompt` отдельно проверяет, что
старые значения не попали в контекст.

## Проверка сценарием

`POST /api/scenario` последовательно меняет четыре факта:

1. срок — `30 ноября`;
2. SMS-требование — `отменено`;
3. подход — `Автоматическая проверка`;
4. версия — `v2`.

После каждого изменения агент отвечает на вопрос об актуальном значении.
Возвращаются `stale_answers`, `stale_mentions`, `old_values_in_prompt` и
пошаговая таблица «было → стало».

В демо: 0 устаревших ответов, 0 упоминаний старых значений, 0 старых
значений в промпте.

## Очистка

`POST /api/task/complete` удаляет `short_term` и `working`, но сохраняет
`fact`. UI показывает количество очищенных записей и число сохранённых
долговременных фактов.

## API

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/health` | состояние сервиса |
| `GET` | `/api/state` | факты, история, рабочая и краткосрочная память |
| `GET` | `/api/policies` | правила замены и накопления |
| `GET` | `/api/prompt` | актуальный промпт и проверка старых значений |
| `POST` | `/api/chat` | вопрос и/или `!fact` / `!decision` |
| `POST` | `/api/task/start` | начать рабочую задачу |
| `POST` | `/api/task/complete` | очистить рабочую и краткосрочную память |
| `POST` | `/api/scenario` | 4 изменения и 4 вопроса |
| `GET` | `/api/audits` | ответы и счётчик устаревших значений |
| `POST` | `/api/reset` | вернуть стартовые факты |

## UI

Отдельная страница `http://localhost:8515`; в общем интерфейсе — раздел
**«Устаревание и конфликты памяти (урок 15)»**.

Вкладки:

- **Проверка памяти** — актуальные факты, последние конфликты, чат, быстрые
  изменения (`!fact`, `!decision`);
- **Сценарий конфликтов** — 4 изменения и 4 вопроса, метрики устаревших
  ответов/упоминаний и таблица «было → стало»;
- **Сценарии добавления** — две кнопки для `append`-фактов:
  «Добавить уникальное значение» и «Добавить повторяющееся значение»;
  счётчики «добавлено / пропущено / всего» и нумерованный список записей;
- **Тестовый диалог** — 9 шагов: 5 перезаписей (срок, подход, SMS,
  статус, версия), 2 добавления решений, проверка дубликата и отдельный
  вопрос-провокация на устаревшее значение. В диалоге видны действия
  «Перезапиши…» / «Добавь…», ответы агента и таблица шагов со статистикой.
- **Правила и очистка** — политики, проверка промпта и кнопка завершения
  задачи.

## Запуск

```bash
cd "Lesson 15/app"
docker compose up -d --build
open http://localhost:8515
curl http://localhost:8015/api/health
```

Порты: API `8015`, UI `8515`; в общем стеке — `/lesson-15/api/*`.
