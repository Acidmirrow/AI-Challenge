# Урок 03 — Способы рассуждений

Тот же чат, что в первом уроке, но модель просят думать по-разному: сразу отвечать,
строить цепочку рассуждений, идти по плану, проверять себя. Разница видна на одной
и той же задаче — и по числу токенов, и по правильности ответа.

Стек как в уроках 01–02: FastAPI (порт 8003) + Streamlit (порт 8503), Python, Docker Compose.

```
front (8503) ── переключатель разделов ──┬─▶ chat API   (8000, урок 01)
                                         ├─▶ format API (8002, урок 02)
                                         └─▶ reasoning  (8003, урок 03) ──▶ DeepSeek / mock
```

Фронт урока 03 — общий интерфейс курса: в сайдбаре переключатель
**«Чат (урок 01)» / «Форматы ответа (урок 02)» / «Способы рассуждений (урок 03)»**.
Первый раздел ходит в API урока 01, второй — в API урока 02, третий — в собственный API
этого урока. Адреса задаются переменными `CHAT_API_BASE_URL`, `FORMAT_API_BASE_URL`,
`REASONING_API_BASE_URL`; для уроков 01–02 в compose добавлен `host.docker.internal`,
потому что те стеки живут в отдельных compose-проектах.

## Способы рассуждений

| id | Что просим у модели | Когда полезно |
|---|---|---|
| `direct` | отвечать сразу, без хода мыслей | простые вопросы, экономия токенов |
| `cot` | рассуждать пошагово, итог — после `---` | счёт, логика, «сколько всего» |
| `cot_few_shot` | тот же формат, но по готовому примеру | когда нужно стабильное оформление |
| `plan_solve` | сначала план, потом выполнение по шагам | многошаговые задачи с условиями |
| `self_check` | ответ, затем отдельная проверка и исправление | там, где легко ошибиться в арифметике |

Стратегия — это только system-промпт плюс правило разбора: ответ делится на
«рассуждение» и «итог» по строке `---`. Для `direct` деления нет — весь текст считается ответом.

## Бесплатные модели

Кроме DeepSeek можно подключить бесплатные тарифы с OpenAI-совместимым API. Модели
появляются в списке сами, как только в `config/secrets.properties` есть ключ:

| Провайдер | Ключ | Что подключается (до 3 моделей) | Что даёт бесплатный тариф |
|---|---|---|---|
| Google AI Studio | `gemini.api.key` | модели `gemini-*` (кроме embedding/tts/image) | контекст 1M, вывод до 65k, лимит по числу запросов в сутки |
| Groq | `groq.api.key` | `llama*`, `gpt-oss*`, `qwen*` | очень быстрый инференс, 128–131k контекста |
| OpenRouter | `openrouter.api.key` | модели с суффиксом `:free` | бесплатные версии моделей |

Список моделей **не хардкодится**: при старте API читает `/models` каждого
провайдера и берёт первые подходящие (3 на провайдера). Поэтому переименование
моделей у провайдера не ломает список. Перечитать без перезапуска:
`POST /api/models/refresh`.

Ключи выдаются без карты: [aistudio.google.com/apikey](https://aistudio.google.com/apikey),
[console.groq.com/keys](https://console.groq.com/keys), [openrouter.ai/keys](https://openrouter.ai/keys).
После правки файла — `docker compose restart api`.

Ограничение бесплатных тарифов — на **число запросов в сутки**, а не на длину ответа,
поэтому окно вывода у них широкое; наш собственный потолок `max_tokens` — 10 000.

## Группа экспертов

В сайдбаре — выпадающий список ролей. Роль одним движением подставляет способ
рассуждения, уровень `reasoning` и температуру, а дальше их можно править руками.

| Роль | Что делает | Стратегия | reasoning | temp |
|---|---|---|---|---|
| Вручную | ничего не навязывает | выбранная | выбранный | выбранная |
| Аналитик | разбирает данные по шагам, ничего не пропускает | `cot` | `high` | 0.2 |
| Инженер | строит решение по плану, опирается на факты | `plan_solve` | `medium` | 0.1 |
| Критик | ищет слабые места и проверяет выводы | `self_check` | `low` | 0.4 |
| Менеджер | коротко и по делу, без рассуждений | `direct` | `none` | 0.7 |

Если у модели нет нужного уровня `reasoning` (например, mock), уровень подменяется
на ближайший доступный, а стратегия и температура применяются как есть. Смена модели
при выбранной роли сохраняет её уровень для новой модели.

## UI

- Сайдбар: переключатель раздела, модель (popover), **группа экспертов**, **выбор способа рассуждения**
  (список стратегий с описанием и system-промптом в раскрывашке) и **три фильтра** —
  `Температура`, `Reasoning`, `Max tokens` (100…10000, шаг 100). Больше ничего:
  остальные ручки урока 02 здесь не нужны.
- Вкладка **«Способы рассуждений»**: окно чата остаётся видимым, а выбранный способ
  показан строкой над ним; смена стратегии в сайдбаре сразу меняет system-промпт
  следующего запроса. Ответ модели приходит двумя блоками: «🧠 Рассуждение» (отдельной раскрывашкой)
  и итоговый ответ; в мете — стратегия, модель, температура, reasoning, время и токены.
- Вкладка **«Сравнение стратегий»**: выпадающий список **«Задача на логику»** с пятью
  уровнями сложности — `extra low` (арифметика), `low` (корзина с фруктами), `medium`
  (поезд с задержкой), `high` (склад и проценты), `extra high` (12 монет на чашечных весах).
  Выбор подставляет текст в поле «Задача», под ним — раскрывашка «Эталонный ответ».
  Задача прогоняется через все стратегии **по одному запросу на стратегию**: видно
  прогресс («CoT: запрос… → готово»), а падение одной стратегии не ломает сравнение —
  её строка просто покажет ошибку. В таблице есть колонка «лимит», которая показывает,
  упёрся ли ответ в `max_tokens`.
  В таблице — токены, время, длина рассуждения, `finish` и сам ответ, ниже — полные тексты.
  Если ответы разошлись, UI так и пишет: «Стратегии разошлись: N разных ответов из 5».
- Вкладка **«Совет экспертов»**: одна задача → ответы группы → проверка другой группой.
  Отвечают **Аналитик** (`cot`, medium), **Инженер** (`plan_solve`, low), **Критик**
  (`self_check`, low) и **Менеджер** (`direct`, none). Проверяют **Аудитор** (арифметика,
  medium), **Логик** (следует ли вывод, medium) и **Председатель** (сводит вердикты, low).
  Ниже — таблица ответов и матрица «эксперт × проверяющий» с вердиктами
  `✅ верно / ❌ ошибка / ❓ спорно / · нет вердикта`, плюс итог каждого проверяющего
  и полный текст его разбора. Задача выбирается тем же списком сложностей.
- Вкладка **«Перекрёстная проверка»**: выбор задачи (`extra low` … `extra high`), две
  выпадашки — **кто отвечает** и **кто проверяет**, плюс общий `Max tokens`. Ответ
  и вердикты проверяющего показываются рядом, в двух колонках.
- Reasoning-уровень модели (`none … max`) — это отдельный механизм: встроенные «размышления»
  DeepSeek, которые приходят в `reasoning_content`, а не наш промпт.

Если ответ не уместился в лимит, UI показывает предупреждение: в чате — «Ответ не
уместился в лимит max_tokens = N…», в перекрёстной проверке — отдельно для ответа
и для разбора проверяющего, в совете экспертов — списком обрезанных участников.

## Перекрёстная проверка

Четвёртая вкладка: задача решается одной моделью, а проверяется другой — без ролей
совета экспертов, только модели из каталога (включая бесплатные Groq).

- пресет задачи выбирается из тех же логических задач, что и в сравнении стратегий
  (`extra low` … `extra high`), текст задачи можно править руками, эталон показан рядом;
- «Модель отвечает» — кто решает (по умолчанию текущая модель чата);
- «Модель проверяет» — кто проверяет (по умолчанию другая модель, отвечающая не выбирается);
- «Max tokens» — общий предел ответа для обеих сторон.

Проверяющий получает задачу и ответ в виде JSON-схемы и возвращает вердикты
`ok | wrong | unclear` плюс итоговый ответ. Если итог совпал, но шаги решения
не показаны, ставится `unclear`, а не `wrong`.

```bash
curl -X POST http://localhost:8003/api/cross-check \
  -H 'Content-Type: application/json' \
  -d '{"prompt": "Сколько будет 17 × 4?", "requirement": "extra low",
       "solver_model": "qwen/qwen3.8-27b", "reviewer_model": "openai/gpt-oss-20b"}'
```

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/health` | статус, провайдер, число стратегий, прочитанные конфиг-файлы |
| GET | `/api/models` | модели и их возможности (`provider`, уровни reasoning, temperature) |
| GET | `/api/strategies` | стратегии: id, label, описание, system-промпт |
| POST | `/api/chat` | `text/event-stream`: `start` → `reasoning`/`delta` → `result`, либо `error` |
| POST | `/api/compare` | по одному прогону каждой стратегии, JSON-ответ |
| GET | `/api/council` | две группы: `solvers` (4) и `reviewers` (3) |
| POST | `/api/council/answer` | ответ одного эксперта: роль + стратегия + reasoning |
| POST | `/api/cross-check` | модель A отвечает, модель B проверяет: ответ + вердикты + итог |
| POST | `/api/council/review` | разбор всех ответов одним проверяющим (JSON-вердикты) |

Тело `/api/chat`:

```json
{
  "model": "deepseek-flash",
  "messages": [{"role": "user", "content": "5 яблок, 3 груши, 2 апельсина…"}],
  "strategy": "cot",
  "temperature": 0.3,
  "reasoning": "none",
  "max_tokens": 1000
}
```

События:

```
event: start    {"strategy":"cot","strategy_label":"Пошаговые рассуждения (CoT)","model":"deepseek-flash", …}
event: reasoning {"text":"…"}          # reasoning_content модели, если включён reasoning
event: delta    {"text":"шаг 1…"}
event: result   {"strategy":"cot","reasoning_part":"шаг 1…","answer_part":"Ответ: 12 фруктов.",
                 "usage":{"completion_tokens":155},"finish_reason":"stop","truncated":false,
                 "elapsed_ms":2033,"max_tokens":1000}
event: error    {"message":"…","kind":"bad_request"}
```

## Тесты

```bash
docker compose exec api pytest -q      # 25 тестов
```

Покрыто: каталог стратегий, разбор ответа по маркеру (включая `direct` и ответ без `---`),
стриминг чата, подстановка system-промпта стратегии, передача температуры/reasoning/лимита,
потолок `max_tokens` (10000 — ок, 10001 — 422), неизвестная стратегия, ошибка провайдера
событием, сравнение всех стратегий и подмножества, совет экспертов и перекрёстная
проверка (ответ одной модели + разбор другой, неизвестная модель — 400).

## Что видно на живой задаче

Задача: «5 яблок, 3 груши, 2 апельсина; два яблока съели, добавили 4 груши — сколько всего?»

| Стратегия | Токенов | Рассуждение | Ответ |
|---|---|---|---|
| Прямой ответ | 4 | — | 10 фруктов ❌ |
| Пошаговые рассуждения (CoT) | 91 | 193 симв. | 12 фруктов ✅ |
| Остальные | — | — | см. вкладку «Сравнение стратегий» |

Вывод урока: «думай по шагам» — не магия, а промпт, который меняет распределение ответов;
на многошаговой арифметике прямой ответ ошибается, а цепочка рассуждений сходится.
Проверять надо оба варианта: CoT тоже иногда ошибается, просто иначе.
